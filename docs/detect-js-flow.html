How DETECT_JS finds signup forms

Runs inside the page, once per frame after every phase. Step numbers match crawl-flow.md, section 5; step 2, the email-input test, is the "email input?" check inside both loops.

top-down bottom-up skipped

scan_page() calls DETECT_JS in one frame

Start the time budget

4 s (DETECT_BUDGET_MS). Both loops below stop early once it is used up.

1Collect roots

The main document plus every open shadow root, checking at most 15,000 elements (MAX_SHADOW_SCAN). All later searches cover this whole list.

3Top-down: start from the form

For each <form> in every root:

Does it contain a visible email input?
no → skip form
yes ↓
Candidate = the <form> detection_method = top-down. Its email inputs are marked claimed.

4Bottom-up: start from the email box

For each <input> in every root:

Claimed, not an email input, or invisible?
yes → skip input
no ↓   set c = parent of the input
↺ climb loop
c is <body>, or already 15 levels up?
yes → skip input
Does c contain a visible submit-like control?
no → c = parent of c, repeat
yes ↓
Candidate = c detection_method = bottom-up. Every input inside c is marked claimed.

Score every candidate

Field count, effective z-index, modal/dialog hint, and form type (subscription, login, checkout, comment, contact, search, unknown).

5Rank (the paper's rules, in order)

  1. Higher z-index first, so popups beat inline forms. Ties: modal hint first.
  2. Anything but a subscription form last.
  3. More fields first.

6Tag and measure each candidate

Sets data-ux-form-id so Python can find the element, then reads:

placement_guessfield types, names & counts pre-checked boxesmissing labels email field attributessubmit text other clickable textheading consent wording size & viewport coverage
